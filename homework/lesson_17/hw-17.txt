1. Теория
1. HTTP (расшифруй и объясни назначение)
HTTP — это HyperText Transfer Protocol, 
протокол передачи гипертекста. Он нужен, чтобы браузер (клиент) мог общаться с сервером: запрашивать страницы,
 отправлять данные, получать ответы. Работает по схеме «запрос — ответ».

2. HTTPS — чем отличается от HTTP?
HTTPS — это тот же HTTP, только с шифрованием. Все данные передаются в зашифрованном виде через TLS/SSL, 
поэтому их нельзя подсмотреть. Ещё HTTPS проверяет подлинность сервера по сертификату. Обычный HTTP работает на порту 80, 
а HTTPS — на 443.

3. Клиент-серверная модель — что это?
Это когда есть клиент, который отправляет запрос, и сервер, который этот запрос обрабатывает и присылает ответ. 
Клиент всегда начинает общение первым, а сервер ждёт запросы. Пример — браузер и сайт.

4. Идемпотентность — что означает?
Это когда один и тот же запрос можно выполнить несколько раз, и результат будет таким же, как после первого раза. Например, 
GET, PUT и DELETE идемпотентны, а POST — нет, потому что каждый раз создаёт что-то новое.

2.1. Разбор запроса
1. Какой метод используется?
POST.

2. Какой путь (endpoint) запрашивается?
/api/users

3. Какая версия HTTP?
HTTP/1.1

4. Что означает заголовок Content-Type?
Он говорит, в каком формате передаются данные в теле запроса. Здесь application/json — значит, тело в формате JSON.

5. Что означает заголовок Authorization?
В нём передаются данные для авторизации. Здесь Bearer eyJ... — это токен, по которому сервер понимает, что пользователь вошёл в систему.

6. Где находится тело запроса?
После пустой строки, в самом конце:
{"name": "Иван", "email": "ivan@mail.com"}

7. Что означает статус-код 201?
201 Created — значит, ресурс успешно создан. Такой код обычно приходит в ответ на POST.

8. Зачем нужен заголовок Location?
Он показывает ссылку на созданный ресурс — /api/users/42, чтобы клиент знал, где его искать.

9. Что находится в теле ответа?
Созданный пользователь в формате JSON:
{"id": 42, "name": "Иван", "email": "ivan@mail.com"}

2.3. Собери запрос сам
Получение списка всех товаров

text
GET /api/products HTTP/1.1
Host: example.com
Создание нового товара с именем "Ноутбук" и ценой 50000

text
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 47

{"name": "Ноутбук", "price": 50000}
Удаление товара с id=7

text
DELETE /api/products/7 HTTP/1.1
Host: example.com
Обновление товара с id=3 (изменить цену на 45000)

text
PUT /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Content-Length: 15

{"price": 45000}
Для обновления одного поля можно было бы использовать PATCH, но PUT тоже подойдёт.
